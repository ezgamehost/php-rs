pack/unpack implement PHP 8.5's integer, floating-point, padded/NUL-terminated
string, hexadecimal, padding and cursor formats. Integer widths and byte order
follow the format; the runtime continues to use 64-bit PHP integers. Formats
support repeat counts and stars; unpack supports offsets, 200-byte field names,
numeric keys, repeated field suffixes, overwrites, and bounds/overflow checks.
The parser preserves native format validation and warning order. String-star
conversion replaces the call argument and updates the active trace, releasing
objects at the native point. Pending exceptions suppress later conversion
callbacks/warnings, while later format errors retain the original exception as
previous. Destructor exceptions after successful conversion leave the string
installed and permit format parsing to continue.

Direct PHP comparisons cover every numeric format, signed/unsigned boundaries,
float byte order, NaN/infinity and overflow warnings, binary strings, odd hex
counts, invalid hex characters (including NUL), zero counts, cursor rewind and
absolute movement, short inputs, field names and numeric keys, strict argument
handling, named arguments, reflection defaults, callback/trace/destructor order,
exception precedence and restored warning delivery. PHP's unpack parameter is
named string, while its offset diagnostic intentionally refers to data.
Existing pack64 and pack FILE bodies were also exercised directly during
implementation; unsupported fixture sections were not rewritten or counted as
suite passes. General engine diagnostic blank-line formatting and binary
non-UTF-8 diagnostic messages remain limitations. This slice does not implement
request memory limits or a 32-bit PHP integer model.
