htmlspecialchars, htmlentities, htmlspecialchars_decode, html_entity_decode
and get_html_translation_table now follow PHP's HTML 4.01, XML1, XHTML and
HTML5 behavior. This includes named aliases, numeric references, multi-codepoint
entities, quote flags, invalid-sequence substitution/ignoring, disallowed-codepoint
rules, preserved existing references when double_encode is false, empty-input
shortcuts, and native charset warning/notice behavior.
All 14 PHP charset modes are handled, including UTF-8, single-byte Unicode maps
and the partial entity support of Big5, Big5-HKSCS, GB2312, Shift-JIS and EUC-JP.
Native malformed multibyte consumption, nonrepresentable references, MacRoman's
ASCII reverse mapping and translation-table ordering are preserved. HTML/ENT
constants are exposed with standard extension metadata.

Mapping data is generated from PHP 8.5.0 html_tables.h: 253/1,511 canonical
HTML4/HTML5 entries and 253/2,125 inverse entries, plus single-byte charset maps
and charset aliases. tools/generate_html_tables.py uses a temporary C extractor;
no C code or external conversion library is used by the Rust runtime. Regenerating
the checked-in table file is byte-identical after rustfmt (SHA256
0dd87192a40dce793ddc8caa3f67eb02eebd9093da723323cd5f1e5b2cda8680).

byte-by-byte encoding combinations, 25,872 numeric-entity decoding cases and

arguments, Stringable conversion, warning/notice shortcuts and throwing-handler
traces. The comparisons exposed and resolved MacRoman reverse-ASCII handling
and nullable encoding parameter labels.
